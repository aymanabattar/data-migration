Migration Agent Platform

A web platform where agents plan, map and verify a data migration, and deterministic engines move the rows. Built on LangGraph, LangChain and Langfuse, with databases and tools hidden behind adapters.

LangGraph LangChain Langfuse Human approval Plain code, no LLM
01

Three libraries, three jobs

They do not overlap. LangGraph decides what runs next, LangChain is how a single step talks to a model, and Langfuse records and scores what happened.

LangGraph

Orchestration and durability
  • Supervisor as a StateGraph; every agent is a subgraph
  • Postgres checkpointer so a run survives a crash
  • interrupt() parks the run at approval gates
  • Send() fans work out per table
  • Streams progress events to the UI

LangChain

Building blocks inside a node
  • Chat model wrapper, so the provider is config
  • Prompt templates
  • Structured output into Pydantic models
  • Tools that wrap connector methods
  • Embeddings and a vector store for column matching

Langfuse

Tracing, prompts, evaluation
  • One callback handler traces graph and chain calls
  • Prompt versions, fetched by name at runtime
  • Cost and latency per migration and per agent
  • Golden datasets and scores for mapping quality

Schema mapper, step by step

The mapping spec is the single source of truth. Target DDL, engine config and validation queries are all generated from the approved version.

# one record of the mapping spec
- target: customers.full_name
  sources: [cust_mst.fname, cust_mst.lname]
  kind: derived            # direct | derived | constant | lookup | dropped
  transform: "TRIM(CONCAT(fname, ' ', lname))"
  target_type: VARCHAR(120)

  confidence: 0.82
  verified: true

06

How the three fit in code

One ranking node and one approval gate, traced end to end. Import paths change between releases; check the current docs of each library before copying.

from langchain.chat_models import init_chat_model
from langgraph.graph import StateGraph, START, END
from langgraph.types import interrupt
from langgraph.checkpoint.postgres import PostgresSaver
from langfuse.langchain import CallbackHandler

# LangChain: provider is config, output is a typed object
llm = init_chat_model(cfg.model, model_provider=cfg.provider)
ranker = rank_prompt | llm.with_structured_output(ColumnMatch)

def rank(state):                       # a graph node
    return {"matches": ranker.batch(state["candidates"])}

def review_gate(state):                # LangGraph: park the run for a human
    decision = interrupt({"spec_uri": state["spec_uri"]})
    return {"approved": decision["approved"]}

g = StateGraph(MapperState)
g.add_node("rank", rank)
g.add_node("verify", verify)           # plain code, no model
g.add_node("review", review_gate)
g.add_edge(START, "rank")
g.add_edge("rank", "verify")
g.add_conditional_edges("verify", retry_or_continue, {"retry": "rank", "ok": "review"})
g.add_edge("review", END)
mapper = g.compile(checkpointer=PostgresSaver(conn))

# Langfuse: one handler traces the graph and every chain inside it
mapper.invoke(inputs, config={
    "configurable": {"thread_id": migration_id},
    "callbacks": [CallbackHandler()],
    "metadata": {"langfuse_tags": ["schema-mapper"], "langfuse_session_id": migration_id},
})

Agents import three contracts and nothing else. A new database or a new migration tool is a new adapter; no agent changes.

08

Safety rules and evaluation

Rules enforced in code

  • Credentials are resolved inside adapters. Prompts and graph state carry a connection id only.
  • The source uses a read-only user.
  • Models see schema and statistics. Samples are masked by the connector first.
  • Every agent-written statement is parsed by the SQL guard. Source accepts SELECT only.
  • Target DDL needs an approval tied to a frozen spec version.
  • Agents cannot issue DROP, TRUNCATE or an unbounded DELETE.
  • Every statement and state change goes to an append-only audit log.

Scores tracked in Langfuse

  • Column match precision and recall against hand-written golden mappings
  • Transform correctness, judged by running the transform and comparing output
  • Wrong mappings that came back with confidence above 0.8
  • Share of mappings a reviewer had to edit
  • Cost and time per migration, split by agent
